# Прозрачность воды — городской пляж Нячанга

Прогноз прозрачности воды (в метрах) у городского пляжа Нячанга на неделю вперёд, по нескольким
стратегиям расчёта, с фактическими наблюдениями и сравнением стратегий. Один файл `index.html`,
без сервера и ключей. Синхронизация между устройствами — через Google Таблицу.

## Файлы

| Файл | Что это |
|---|---|
| `site/index.html` | Сам виджет. Эту папку и публикуем. |
| `apps-script.gs` | Код синхронизации для Google Таблицы. В папку сайта не класть. |
| `README.md` | Этот файл. В папку сайта не класть. |
| `nhatrang-water-доступы.md` | Адрес сайта, таблицы, аккаунт. В папку сайта не класть, пароли и ключ туда не писать. |

## Как пользоваться

- **Место** — выпадающий список вверху. По умолчанию Нячанг, городской пляж. «Другое место…» —
  поиск по названию (Open-Meteo Geocoding), найденное добавляется в список. У каждого места свой лог
  и свои наблюдения. Для мест кроме Нячанга: одна точка для погоды и моря, река не учитывается,
  сезонная норма и коэффициенты нячангские — прогноз грубый, пока не накопятся замеры.

- **Два окна:** прогноз и факт отдельно на утро 05–10 и вечер 15–18. Наверху для каждого окна —
  видимость, температура воды и воздуха, УФ-индекс (максимум за окно) и прилив/отлив в окне;
  ниже — время полной и малой воды на сегодня.
- **Факт** — в таблице «По дням», в строке даты и окна: видимость в метрах (`3,5`) или отклонение
  от основного прогноза (`+1`, `-2`), Enter. Пусто — удалить. Время записывается само
  (если вводишь за сегодня), место и способ замера — из настроек внизу страницы.
- Под прогнозом каждой стратегии — её ошибка относительно факта: плюс — завысила, минус — занизила.
- **Стратегии** — таблица со средней ошибкой, смещением и числом наблюдений по каждой стратегии
  и горизонту: по фактической погоде, на сегодня, на 1–2 дня, на 3–6 дней.
- **Основная стратегия** (крупная цифра наверху) — выбирается вручную или «Авто»: лучшая по средней
  ошибке на 1–2 дня, когда наберётся от 5 наблюдений.
- Способ замера держать одним и тем же, иначе цифры несравнимы.

## Как устроено

**Снимки входных данных.** При каждом открытии страница берёт данные Open-Meteo и сохраняет на каждую
дату снимок: почасово (с 12:00 предыдущего дня до конца дня) дождь в городе, в бассейне реки Кай и в верховьях Кай (`rainU`, среднее 3 точек),
ветер (скорость, направление), облачность, температуру воздуха, УФ-индекс, волну (высота, период, направление), уровень моря,
температуру воды, течение; по дням — дождь за 7 предыдущих дней (город, бассейн, верховья), расход реки и его медиану, расход и медиану за 4 дня (`qs`, `qmeds`: d−3…d).
- прошлые дни (30 дней назад): один снимок на дату по фактической погоде, ключ `ДАТА|an`;
- будущие дни: отдельный снимок на каждый день выпуска прогноза, ключ `ДАТА|ДЕНЬ_ВЫПУСКА`.

Снимок сохраняется, даже если какие-то данные сейчас ни одна стратегия не использует, —
чтобы новые стратегии можно было проверить на всей истории.

**Стратегия = алгоритм + набор данных из снимка.** Все активные и фоновые стратегии считаются по всем снимкам,
результаты лежат в снимке (`p: {id: метры}`). Новая стратегия при первом запуске сразу
пересчитывается по всей истории.

**Правила развития:**
- стратегия неизменяема: любая правка формулы или данных — новая стратегия с новым `id`;
- старая получает `status: "archived"`: перестаёт считаться, её история и метрики остаются;
- выводы о стратегии — не раньше 15–20 наблюдений;
- стратегия, которая не обыгрывает «Сезон», не нужна;
- новые стратегии сначала фоновые (`status: "shadow"`): считаются по всем снимкам, есть в статистике и в подсказке,
  но в «Авто» не участвуют и колонок в таблице дней не имеют; основной их делает только пользователь (селектор основной);
- «выигрышную» выбирает пользователь по статистике после 15–20 наблюдений; автоматически основная не переключается на фоновую.

**Статистика.** В таблице стратегий: средняя ошибка / сдвиг / число по срокам прогноза и «Ближе всех» —
сколько раз из числа наблюдений стратегия была ближе всех к факту (по снимку, показанному на этот день; ничья ±0.05 м — победа обеим).
Наблюдение сохраняет прогнозы всех стратегий на момент ввода (`pred: {id: м}`, `predSnap`). Всё попадает в «Скачать лог».

**Подсказка.** Наведение (на телефоне — нажатие) на значение прозрачности — большое число окна или ячейку стратегии в таблице дней —
показывает список: стратегия, прогноз, разница с основной.

**Текущие стратегии:**

| id | Название | Суть |
|---|---|---|
| `season` | Сезон | Только сезонная норма по месяцам (3, 4, 5, 6, 7, 6.5, 6.5, 6, 5, 3, 2, 2.5 м). Базовая линия. |
| `persist` | Вчера | Последнее наблюдение до дня выпуска, не старше 5 дней. Базовая линия. |
| `beach-v2` | Пляж v2 | Как v1, но отдельно на каждое окно: волна — макс. с 12:00 накануне до конца окна, ветер — средний по окну. Остальное как в v1. Основная по умолчанию. |
| `beach-v3a` | Прилив ↑ (фон) | Пляж v2 × (1 + min(0.2, max(0, ΔL/0.1·0.07))), ΔL — подъём уровня моря за окно. Отлив не штрафуется. «В прилив прозрачность выше прогноза» — вариант «вода прибывает». |
| `beach-v3b` | Высокая вода (фон) | Пляж v2 × (1 + clamp(L̄,0,0.3)/0.3·0.2), L̄ — средний уровень в окне от среднего моря. Вариант «вода стоит высоко». |
| `beach-v4` | Река Кай (фон) | Как v2, но река с запаздыванием и сильнее: R = max(1+(Q/Qмед−1)·k) по d (k=1), d−1 (0.8), d−2 (0.6); поправка `max(0.3, 1/(1+max(0,R−1)·0.6))`. Расход — Open-Meteo Flood API (GloFAS, модель); нет данных в точке → не считается, предупреждение в строке сообщений. |
| `beach-v5` | Дожди в верховьях (фон) | Сезон × волна × ветер (как v2) × местный дождь (только город, формула v1) × муть верховий. Муть: дождь в 3 точках верховий (12.27/108.89, 12.36/108.78, 12.20/108.80, среднее) → «ведро» почвы 15 мм, сохнет 5 мм/сут, излишек → ядро задержки: 0 до 8 ч, линейно до пика 24 ч, дальше exp(−(t−24)/36 ч) (река ~80 км, волна ~1–1.5 м/с, рассеяние 2–3 сут); дни −7…−2 суточными суммами (полдень), дальше почасово. Ветер (с 12:00 накануне до конца окна): с С/СВ (20°) ×1, с Ю ×0.5, `0.75+0.25·cos(dir−20°)`, штиль < 5 км/ч ×0.8 (устье севернее пляжа). Поправка `1/(1+0.02·муть·ветер)`. Река GloFAS не используется. Все коэффициенты — стартовые, в константах `UP5`. |
| `beach-v1` | Пляж v1 (архив) | Норма × поправки: дождь `1/(1+R/25)`, где R = 0.6·сегодня + 1.0·вчера + 0.6·позавчера + 0.3·3 дня назад (дождь дня = 0.4·город + 0.6·бассейн); прибой `1/(1+max(0,H−0.4)·1.4)`, H — макс. волна 12:00 вчера … 18:00 сегодня; ветер `1/(1+max(0,W−12)/35·k)`, W — средний 06–18, k = 1.3 с моря (30–160°), 0.7 с берега; река `max(0.4, 1/(1+max(0,Q/Qмед−1)·0.4))`. Итог 0.3–15 м. |

Стратегии описаны в `index.html`, массив `STRATEGIES`: `id`, `name`, `status`, `desc`, `data`, `compute(снимок, окно, ctx)`.
Окна — массив `WINS`. Прогнозы в снимке хранятся как `p["стратегия@окно"]`, например `beach-v2@am`.

**Прилив** — уровень моря из Open-Meteo Marine, в метрах относительно среднего уровня моря (модель,
не портовая таблица приливов; время пиков может расходиться на час-другой).

## Данные и хранение

- **Google Таблица** — основная полная копия: листы `snaps` (снимки) и `obs_v2` (наблюдения),
  строка на запись, данные в JSON.
- **Браузер** — рабочая копия (localStorage `ntClarity.v2`) и очередь неотправленного
  (`ntClarity.pending2`). Полные снимки локально хранятся 60 дней, старше — только прогнозы стратегий.
- **Скачать лог** (внизу страницы) — JSON со стратегиями, снимками и наблюдениями.

Наблюдение: `id` = `ДАТА|am` или `ДАТА|pm`, `date`, `win`, `actual` (м), `time`, `place`, `method`, `ref` (если вводилось как ±: от какой
стратегии и какого значения), `updated`, `deleted`.

Одно окно одной даты — одно наблюдение; правка с любого устройства равноправна, действует последняя.

## Синхронизация между устройствами

**Настройка (один раз):**
1. Создать пустую Google Таблицу.
2. Расширения → Apps Script, удалить всё, вставить `apps-script.gs`.
3. В первой строке заменить `ПРИДУМАЙ-СВОЁ-СЛОВО` на своё слово (ключ). Сохранить.
4. Развернуть → Новое развертывание → Веб-приложение. Запуск от имени: «Я». Доступ: «Все».
   Развернуть, разрешить доступ к таблице.
5. Скопировать URL веб-приложения (`…/exec`).
6. На сайте внизу: «Синхронизация» → URL → ключ.
7. «Ссылка для другого устройства» → открыть эту ссылку на остальных устройствах.

Статус — вверху страницы: «синхронизация: ok» или что не отправилось.

Обновление кода скрипта: Развернуть → Управление развертываниями → карандаш → Версия «Новая» →
Развернуть. URL не меняется.

## Публикация (Netlify, бесплатно)

**Первый раз:**
1. Папка `site` с одним `index.html`.
2. https://app.netlify.com/drop — перетащить папку.
3. Сразу закрепить сайт (Claim), войти через Google или GitHub — иначе через 24 часа удалится.
4. Site configuration → Change site name → например `nhatrang-water`.
5. Записать адрес в `nhatrang-water-доступы.md`.

**Обновить:** заменить `index.html` в папке → app.netlify.com → сайт → Deploys → перетащить папку.
Данные не теряются.

**Телефон:** открыть адрес → меню браузера → «Добавить на главный экран».

## Если что-то не работает

- Строка под прогнозом пишет, какой сервис не ответил и что ответил.
- «Нет живых данных — показаны сохранённые»: нет интернета или Open-Meteo недоступен.
- «синхронизация: ошибка: bad key» — ключ на странице не совпадает с KEY в скрипте.
- Пропало на устройстве — открыть «Ссылку для другого устройства» заново, всё подтянется из таблицы.
