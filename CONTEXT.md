Прочитай этот файл, затем `README.md` (заплыв) и `nhatrang-water/README.md` (прозрачность) — там все требования.
По ним программу можно пересобрать с нуля. Первый запуск в новой сессии — по `START.md`.

## Репозиторий
- GitHub: `sklddjewiodjewi/swim-tool` (private). Ветка `main`.
- После каждой «генери»: коммит + push, пользователю — короткий итог и файл `swim_tool.html`
  (он открывает его локально из «Загрузок»).

## Кто и зачем
- Хобби-проект одного человека (Михаил): плавает в море в Нячанге (Вьетнам), в ластах, иногда с лопатками;
  цель — длиннее дистанция и выше средняя скорость. Часовой пояс пользователя — Asia/Novosibirsk (UTC+7).
- «Пользователь» в требованиях — роль. Все замеры — от одного человека, устройства равноправны.
- Ссылки открываются в Chrome (Windows). Файл открывается локально (`file://…/Downloads/swim_tool_N.html`);
  Chrome дописывает к повторным загрузкам `_2`, `(1)` и т. п.

## Правила работы (заданы пользователем, соблюдать)
- Ответы короткие, тезисами.
- **Копить замечания и НЕ генерировать код, пока пользователь не скажет «генери».** До этого — только
  ответ «записал в очередь» с описанием, что будет сделано.
- Отвечать только на заданный вопрос, ничего не додумывать, лишних функций без просьбы не добавлять.
- После «генери»: сделать всю очередь, проверить (тесты + браузер), обновить README (требования!), прислать файлы.
- Любой новый параметр в расчёте дистанции/энергии — обязательно в подсказки-составляющие 📏 / 🔥
  (полоса итогов, строки истории, строка Σ).
- Прозрачность: стратегии неизменяемы (правка = новый id, старая → архив); выводы не раньше 15–20 наблюдений;
  цикл: копим факты → лог JSON → разбор → новая стратегия → сравнение. Новые стратегии сначала фоновые (`shadow`).
- Секреты (ключ Apps Script KEY, ссылка `#sync=…`, пароли) — никогда не в репозиторий и не в файлы.
