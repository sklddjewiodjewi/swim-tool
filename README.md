# Морской навигатор заплыва

Одна HTML-страница (`swim_tool.html`), без сборки. Карта: Leaflet + спутник Esri, берег: OpenStreetMap (нужен интернет).
Хобби-утилита для одного человека: считать заплывы в море вдоль берега, честно оценивать нагрузку и вести историю.

## Что делает
- По точке входа и разворотам строит трек вдоль берега и считает дистанцию (+ рысканье).
- По дистанции, времени, весу и воде считает скорость, ккал, углеводы, жир, жидкость и потерю веса.
- Учитывает ветер и течение по часам (Open-Meteo): дистанция — геометрия, ветер меняет цену километра.
- Ведёт историю: факты и планы; записи создаются только явно.
- Отдельная страница «Прозрачность воды» (проект nhatrang-water, v3.7); на главной — группа погоды ближайшего окна.

## Как пользоваться
1. Двойной клик на берегу ставит 🟢 старт/выход.
2. Двойной клик по берегу ставит 🔴 развороты (ориентиры, видные из воды). Их может быть несколько, обход по порядку кликов.
   Пример «в обе стороны от захода»: старт, A в одну сторону, B в другую.
3. Трек сам строится вдоль берега (подсказка «✓ по берегу OSM»; «⚠️ без берега» — прямыми, тогда есть «⇄ море»).
4. Задать удаление (иконка: две кривые и стрелка) (м), 〽️ рысканье (%), 🕐 время «с … по …» (⏱ посчитается; без «по» — ⏱ вручную, ч дробью), ⚖️ вес, 🌡 воду.
   С 🕐 подтягивается ветер/течение по часам — 🌬 показывает поправку цены км (×1.07 — дороже штиля).
5. При открытии — черновик по последнему факту («✏️ черновик — не сохранено»). Проплыл — поправил — **✅ Записать**.
   После этого правки записи сохраняются сами.
6. 📝 — план на завтра: задать 🎯 км **или** 🎯 🔥 ккал, кликнуть фиолетовую стрелку у крайней точки — точка
   сдвинется до цели. **📝 Запланировать** — сохранить план. Пришёл день, проплыл — **✓** в строке плана.
7. Клик по строке истории — открыть эту запись (как смена даты в 📅), ничего не перезаписывается. ⧉ в строке —
   взять её маршрут и параметры в открытую дату (Ctrl+Z — откат).
8. ✕ рядом с датой или в строке удаляет запись. Правый клик по точке удаляет её, Ctrl+Z отменяет, 🗑️ очищает.
9. Кнопка «линия берега» (квадратик суша/море) — показать исходную линию берега OSM (пунктир и узлы). Сплиттер между историей и картой тянется.
10. 🐞 — скачать отладочный файл (лог, состояние, история, сырой берег) для разбора ошибок.
11. Группа погоды — первая строка шапки, над параметрами — ближайшее окно: 👁 прозрачность, 🔆 УФ, 🌤 воздух, 🌊 вода,
    🌙 прилив/отлив, 💨 ветер.
    Клик — страница прозрачности, «← Заплыв» — обратно. Слова — в подсказках.

## Понятия
- **Ориентир / разворот**: точка на берегу, до которой плывёшь и поворачиваешь.
- **Удаление** (иконка: берег и линия заплыва, между ними стрелка): насколько далеко от берега плывёшь вдоль него.
- **Рысканье 〽️**: надбавка к дистанции за неровный курс (ушёл вглубь, вернулся, обплыл кого-то).
- **Трек**: старт → по косой в воду → вдоль берега к разворотам по порядку → обратно → старт.
- **Черновик**: значения на экране без записи в истории. **Факт**: проплытый заплыв. **План**: заплыв на будущее.

## Иконки
📏 дистанция км · ⏱ время ч · 🏊 скорость км/ч · 🌡 вода (☀️ >24° / 🌤 18–23° / ❄️ <18°) ·
⚖️ вес кг · 🔥 ккал · 🍺 углеводы г · 🐻 жир г · 💧 жидкость л · 📉 потеря веса кг · «удаление» удаление м · 〽️ рысканье % ·
🕐 время старта · 🌬 поправка цены км за ветер/течение · 📍 курорт (флаг) · 👁 прозрачность воды.
У всех иконок подсказки при наведении.

# Требования (для пересборки с нуля)

## Общее
- Одна HTML-страница, только браузер, без сервера. Интерфейс на русском.
- Пользователь один и тот же: минимум пояснений, иконки вместо слов, компактно.
- Смысл — честно оценивать нагрузку, не приписывая себе лишнего: записи только явно, рысканье из данных, а не «на глаз».
- У каждой иконки (поля, результаты, шапка таблицы, агрегаты) подсказка при наведении.
  Подсказки свои (div #tip, не системный title): эмодзи цветные, иконки переносятся в несколько рядов.
  Подсказка сбоку от элемента (справа, если не влезает — слева), по центру его высоты, не перекрывает соседние строки;
  ячейка с шуточной подсказкой подсвечивается оранжевой рамкой.
- Курорт (иконка — красная «перевёрнутая капля», как метка на картах, SVG): встроенные Нячанг (по умолчанию),
  Фукуок (Зыонг Донг), Пхукет, Сочи, Дубай + свои: «Другой курорт…» — поиск Open-Meteo Geocoding, найденное
  добавляется в список (`swim.resorts.v1`), «Убрать … из списка» — для своего. Смена курорта центрирует карту и очищает точки.
  Один курорт на обе страницы: прозрачность берёт его из заплыва.
- Масштаб карты — шаг ¼ (кнопки +/−), колесо медленнее (`zoomSnap/zoomDelta 0.25, wheelPxPerZoomLevel 240`).
- Шапка: погода ближайшего окна · параметры маршрута · параметры заплыва · результаты.
- Все элементы шапки (поля, кнопки, значок 👁) одной высоты (`--ctl-h`, 34 px).
- Строка подсказок под параметрами в норме пустая; показывает только предупреждения («⚠️ без берега — прямые», «⏳ берег…»)
  и подсказки, пока не поставлены старт и разворот.
- Компоновка: слева шапка + история, справа карта на всю высоту окна; между ними сплиттер (ширина запоминается,
  двойной клик — 50/50); на узком экране друг под другом, без сплиттера.

## Карта и точки
- Двойной клик: первая точка = старт/выход, остальные = развороты, обходятся по порядку кликов, в конце возврат на старт.
- Точки перетаскиваются, пересчёт при перетаскивании не чаще кадра отрисовки. Правый клик по точке удаляет её.
- Ctrl+Z отменяет действия с точками (добавление, перетаскивание, удаление, очистка, сдвиг планом), много шагов.
  В полях ввода Ctrl+Z обычный.
- Слияние: точки ближе 15 px на экране — одна точка. Двойной клик на существующую точку новую не ставит.
  Перетащили точку на другую — одна убирается; если среди них старт, остаётся старт.
- После клика по стрелке плана или по точке 0.6 с двойной клик по карте игнорируется
  (иначе привычный «двойной клик» по стрелке ставил лишнюю точку там, где была стрелка).
- Кнопка «линия берега»: исходная линия берега OSM белым пунктиром + узлы жёлтыми точками (видно, какая детальность у данных).

## Трек: модель «коридор»
- **Главное в калькуляторе**: трек близок к реальной траектории человека, а не хорда. Берег любой, считается сам.
- Как плывёт человек: от берега по косой, затем держит удаление, повторяя изгибы берега, но мелкие не повторяет.
- Требование к алгоритму: никакой немонотонности и разваливания на крайних значениях параметров.
  (Старая схема «сгладить берег скользящим средним → сдвинуть в море» была отвергнута: сглаживание сдвигало линию
  относительно берега, при больших окнах форма разваливалась, на внутренних углах сдвиг давал петли —
  дистанция вела себя немонотонно.)

### Алгоритм
1. Берег: OSM `natural=coastline` через Overpass API (overpass-api.de, запасной overpass.kumi.systems),
   область = точки ± ~3 км. Куски склеиваются в цепочки. Кэш в localStorage; новый запрос, только если
   точки подошли к краю области кэша ближе ~1 км (у края данные берега обрываются).
2. В OSM у coastline вода всегда справа — сторона моря определяется сама.
3. Цепочка, ближайшая к старту (не дальше 1.5 км, иначе запасная модель). Узлы OSM как есть, параметр s — метры вдоль берега,
   сетка 50 м для быстрых запросов «ближайшая точка берега (со знаком вода/суша)» и «пересекает ли отрезок берег».
4. Осевая линия: точки берега через 5 м, сдвинутые по нормали в воду на «удаление»; точки, оказавшиеся ближе «удаление» к берегу
   (петли на внутренних углах), выкидываются. Строится один раз на (берег, «удаление») и кэшируется.
5. Коридор: удаление от берега в пределах «удаление» ± 15 м (ширина CORRIDOR_M = 30 м, фиксированная, не параметр интерфейса;
   гасит шум данных берега).
6. Путь по коридору — жадно: из текущей точки к самой дальней точке осевой (бинарный поиск), хорда к которой
   не пересекает берег и вся лежит в коридоре (проверка каждые 15 м). Шире коридор ⇒ хорды длиннее ⇒ путь короче:
   монотонность по построению.
7. Вход/выход: старт проецируется на кромку воды; у первого/последнего участка нижняя граница коридора растёт
   по косой (1 м от берега на 3 м пути) — косой вход получается сам.
8. Последовательность: старт → развороты по порядку → старт. Разворот = точка осевой, ближайшая к ориентиру ПО РАССТОЯНИЮ
   среди точек в пределах ±3 «удалений» по s от проекции ориентира; почти равные (±0.5 м) — та, что ближе к старту по s.
   (Выбор «ближайшая по s» у выпуклого угла — край набережной, пирс — уводил разворот за угол: все точки осевой
   у угла проецируются в сам угол.) Старт — по-прежнему точка осевой против своей проекции.
   Участки кэшируются: при перетаскивании пересчитываются только участки у сдвинутой точки.
9. Дистанция по берегу = сумма участков (гаверсинус). 📏 = по берегу × (1 + 〽️/100).
10. Пока берег грузится, автосохранение ждёт.
- Проверено тестами: на синтетических берегах (пляж, бухта, шум кромки 0/8/20 м) дистанция монотонно не растёт
  при расширении коридора 0 → 10⁶ м; пересчёт с кэшем ~70 мс на 15 км.

### Запасная модель (нет сети / нет берега в OSM)
- Ось берега = от старта к самой дальней точке. Все точки сдвигаются на удаление перпендикулярно оси; трек прямыми.
- Сторона моря кнопкой «⇄ море» (видна только в этой модели). В подсказке «⚠️ без берега», в истории ⚠️.

### Отрисовка
- Цвет по направлению вдоль берега: в одну сторону голубой, в другую оранжевый; стрелки по ходу каждые ~120 px.
- Оранжевые участки смещены на 5 px в сторону моря, чтобы не слипались с голубыми (только визуально).

## Рысканье 〽️
- Надбавка к дистанции за реальный неровный курс. Вклад рысканья больше, чем детали береговой линии.
- По умолчанию **9 %**: Univ. of Kent (SwimAR), 17 пловцов с GPS в озере проплыли в среднем на 9 % больше маршрута.
  Цифры с соревнований (Swim Smooth: +8…24 %) не взяты — в них волна и погрешность GPS на руке.
- Хранится в каждой записи. Старые записи без 〽️ открываются с 0 % (дистанция не меняется задним числом);
  как шаблон для новой даты — с 9 %.
- Подсказка у 📏: «По берегу X км + 〽️ N % = Y км (метры)».

## Ветер и течение 🌬
- 📏 — только геометрия (по берегу + 〽️). Ветер, течение и волнение меняют только «цену километра» (ккал и всё от них).
- Данные: Open-Meteo, по часам, местное время курорта (`timezone=auto`), точка — старт:
  ветер 10 м — Forecast API (`start_date=end_date=дата`), при отказе — Archive API (ERA5);
  течение (скорость, куда течёт), волна, ветровая волна — Marine API (`cell_selection=sea`).
  Кэш `swim.wx.v1` по (дата, старт с точностью 0.01°); сегодня/будущее перезапрашивается раз в 3 ч.
- Нужно 🕐 время «с». Скорость в воде считается равномерной.
- Модель: трек (с 〽️, длины нормированы на 📏) режется на куски по 100 м; на каждом куске по времени прохождения
  берётся ветер/течение (линейно между часами); поток воды раскладывается на «вдоль» и «поперёк» участка;
  скорость по треку g = √(v² − поперёк²) + вдоль. Подбирается скорость пловца v относительно воды, при которой
  суммарное время = ⏱ (бисекция). Ккал — по MET от v, а не от скорости по берегу.
- **Консервативно** (лучше недооценить нагрузку, чем переоценить):
  ветровой снос = 1.3 % скорости ветра для встречной и боковой составляющей (нижняя граница 1.3–2 %), 2 % для попутной;
  модельное течение (сетка ~8 км, «не для прибрежной навигации»): мешающее ×0.5, помогающее ×1;
  волнение — 0 (надёжной связи «волна → цена км» в источниках нет). Следствие: постоянный ветер/течение туда-обратно
  даёт цену чуть ниже штиля (~×0.99) — это сознательный перекос в сторону недооценки.
- Нет 🕐 «с» / нет сети / нет данных: поправки нет (цена как в штиль), 🌬 — ⚠️ с причиной в подсказке.
- Подсказка 🌬: ветер (м/с, откуда), течение, волна, скорость в воде и по берегу, «📏 в штиль» (= v × время),
  цена км ×F и «штиль X → Y ккал».
- План: время = симуляция при средней скорости в воде по фактам (`stillKm / hours`; нет — средняя по берегу);
  план по ккал использует цену км с прогнозом ветра.
- В записи сохраняется: `startTime, waterKmh, stillKm, costF, wx:{wind, windFrom, cur, wave, windWave}` —
  для личной статистики (через 15–20 заплывов подобрать свои коэффициенты ветра/волны; брать нижнюю границу).
- Проверено тестами: штиль → ×1.00; встречный туда и обратно (ветер развернулся) ×1.08; попутный туда и обратно ×0.87;
  постоянный ветер ×0.995; без 🕐/сети — без поправки.

## Энергия
- Входы: дистанция 📏 (с рысканьем), время в часах дробью (1.5), вес, вода, ветер/течение (см. выше).
- Скорость по берегу = дистанция / время (не вводится). Нагрузка — от скорости относительно воды (без погоды — по берегу).
- Ккал = MET × 3.5 × вес / 200 × минуты. MET от скорости (ласты), линейно между точками:
  0 → 4, 1.5 → 6, 2.4 → 8.5, 3.5 → 11, 5 → 13 (дальше 13). Плюс вода: +1.2 прохладная, +2.8 холодная.
- Углеводы: 60 г/ч (холодная 80 г/ч) при 2.4 км/ч, × MET/8.5. Жир = ккал / 7700 кг.
- 💧 Жидкость = 0.6 л/ч × время. 📉 Потеря веса = жир + жидкость + 0.3 кг константа.
- Результаты одной строкой: 📏 первой и крупнее, далее 🏊 🔥 🍺 🐻 💧 📉.
- Формат строки составляющей: «Название: значение ед. (доля %)», отрицательные — со знаком «−». Порядок: база/трек →
  рысканье → ветер и течение → вода → округление/прочее.
- **Подсказки-составляющие 📏 и 🔥** (обязательное правило): при наведении на весь блок (иконка + число; число
  подчёркнуто пунктиром) — из чего сложен итог; клик по блоку — то же в окошке, которое не исчезает, пока не кликнуть
  мимо или ✕ (и для телефона), каждая часть с
  вкладом в процентах от итога, сумма частей = итог. **Любой новый параметр или нюанс в расчёте дистанции или
  энергии обязательно добавляется в эту подсказку со своим вкладом** (даже если вклад 0 — с пояснением).
  - 📏: прямые между разворотами по воде (хорды участков без входа/выхода) + вход и выход (уклон 1:3, до 0.95 удаления)
    + огибание берега на удалении (остаток трека, ≥ 0; без берега — «сдвиг в море») + 〽️ рысканье;
    строка «Ветер и течение: 0 % — длину не меняют, влияют на время и калории».
  - 🔥: части MET по очереди, каждая × 3.5·вес/200·мин: база — MET по скорости по треку без рысканья;
    〽️ рысканье — MET(скорость с рысканьем) − база; 🌬 ветер и течение — MET(скорость в воде) − MET(по берегу)
    (может быть минус); 🌡 вода — надбавка +1.2/+2.8. Внизу: вес и время — множители всех частей.
  - То же в таблице истории: в каждой строке на ячейках 📏 и 🔥 (подчёркнуты пунктиром) — составляющие этой записи;
    в строке Σ — сумма каждой составляющей по всем заплывам без планов и её доля. Запись хранит `distParts`
    {straight, entry, bend (км), depth}; у старых записей без неё — «трек вдоль берега» + рысканье. 🔥 записи считается
    из её полей (baseKm, rysk, hours, weight, water, waterKmh); расхождение со старой формулой — строка «Прочее».
- Шуточные подсказки (результаты, ячейки истории, агрегаты): 🐻 → полоски 🥓 (1 ≈ 3 г жира),
  🍺 → кружки 🍺 (0.5 л ≈ 18 г), 💧 → бутылочки 0.5 л. До 20 иконок рядом, больше — «🥓 × 33». Подчёркнуты пунктиром.

## Точность (везде одинаково)
- Не показывать больше знаков, чем позволяет погрешность модели.
- км, км/ч, кг, л: 1 знак. ккал, углеводы, жир: до десятков. Вес: целое. Время: как введено (до 0.01).
  Точная дистанция (до метра) — в подсказке 📏 и в логе.

## Записи: черновик, факт, план
- «Текущая запись» = запись за дату в 📅.
- Нет записи — **черновик**: в статусе «✏️ черновик — не сохранено», правки ничего не пишут в историю.
- Создание только явно: **✅ Записать** (дата сегодня или раньше) / **[иконка плана] Запланировать** (дата позже сегодня).
- Правки созданной записи сохраняются сами (пауза 0.7 с). После удаления правки запись не пересоздают.
- `openDate` — дата, чьи значения сейчас в форме; автосохранение пишет **только** в запись `openDate`, никогда в чужую.
- При открытии: есть запись за сегодня — она; есть черновик за сегодня — он; иначе черновик по **последнему факту**
  (не по плану); нет фактов — по прошлому состоянию.
- **Клик по строке истории = открыть запись этой даты** (то же, что смена 📅): форма и карта — её значения, строка
  подсвечена, ничего не перезаписывается и вопросов нет. По текущей строке клик ничего не делает.
- **Уход с даты** (клик по строке, смена 📅, план на завтра, «✓ выполнено», закрытие/обновление страницы):
  есть запись и несохранённые правки — сохраняются сразу (не ждать 0.7 с); записи нет — черновик запоминается
  за этой датой (`swim.drafts.v1`, до «Записать» или 60 дней) и при возврате на дату подставляется.
- Открыта дата без записи и без черновика — значения формы остаются черновиком этой даты (как шаблон).
- **Копирование — только кнопкой ⧉** в строке (у открытой строки её нет): маршрут и параметры записи (точки, удаление,
  рысканье, вес, вода, время «с–по», план) → в открытую дату; дата и 👁 не копируются. В черновик — без вопроса;
  в существующую запись — «Заменить запись дд.мм значениями от дд.мм?» (**единственное место перезаписи**).
  Ctrl+Z откатывает копирование целиком (стек отмены хранит снимок всей формы).

## План
- Кнопка плана (своя SVG-иконка: свиток со слева закрученным краем, на листе растущий график, на вершине флажок,
  снизу базовая линия; цвет — currentColor) — дата = завтра; есть план — подставляется; нет — черновик плана (создать — «📝 Запланировать»).
- Планов может быть сколько угодно, на любые будущие даты. Удаляются ✕.
- Цель: 🎯 км **или** 🎯 🔥 ккал — второе поле считается само. Запоминается, по чему задан план (`planBy`):
  при смене веса/воды пересчитывается второе поле. В плане скорость = средняя по фактам ⇒ ккал ∝ км:
  км = ккал / (ккал на 1 км при средней скорости, весе, воде).
- Время: интервал «с … по …» (местное) → ⏱ = по − с (через полночь +24 ч), ⏱ только для чтения.
  Без «по» — ⏱ вручную. В плане «по» = «с» + расчётное время, только для чтения.
- Время в плане считается само и не редактируется: дистанция / средняя скорость по фактам (Σкм / Σч;
  нет фактов — 2.4 км/ч), шаг 0.05 ч.
- Рядом с целью: Δ до цели или ✓.
- Толстые фиолетовые стрелки у крайних разворотов (самый дальний по каждую сторону от старта): наружу — продлить,
  внутрь — укоротить. Клик по стрелке/крайней точке сдвигает её вдоль берега (точка остаётся на берегу) до 📏 = 🎯.
  Шаг = Δ / 2 / (1 + 〽️) (туда и обратно, рысканье), затухание ×0.5 если не сходится, до 15 итераций, ±5 м.
  Через старт не перескакивает (≥ 20 м). Подошла к краю загруженного берега — берег догружается («⏳ догружаю берег…»),
  подбор продолжается сам. Не сошлось (|Δ| > 20 м) — «⚠️ не сошлось, Δ …».
- Режим плана: шапка серая с плашкой «📝 ПЛАН на дд.мм».
- В истории планы: серый фон, серый курсив, 📝. Пропущенный план (дата прошла) — ещё и зачёркнут.
- В день плана и позже — кнопка **✓** в строке: план → факт (флаг снимается, запись открывается для правки времени и точек).
  Без ✓ план остаётся планом и в итоги не входит.

## История
- Таблица: дата + показатели, новые сверху; текущая дата подсвечена. ✕ — удалить (с подтверждением).
- Шапка колонок — иконки с подсказками: 📅 📏 ⏱ 🏊 🌡 ⚖️ 🔥 🍺 🐻 💧 📉 👁 📍. Дата `дд.мм`, год только если не текущий.
- Курорт — последняя колонка (иконка-метка в шапке), очень компактно: 3 буквы (НЯЧ, ФУК, ПХУ, СОЧ, ДУБ; у своих —
  первые 3 буквы названия), полное название в подсказке. Эмодзи-флаги не подходят: Windows рисует их буквами «VN».
  В записи хранятся `locName`, `locShort` — подпись сохранится, даже если свой курорт убран из списка.
- Вторая строка шапки — итоги (тем же фоном, что шапка, отделены тонкой белой линией), только по фактам:
  Σ число заплывов, км, ч, ккал, углеводы, жир, жидкость; среднее вес, потеря; скорость = Σкм / Σч.
- Масштаб и положение карты сохраняются и восстанавливаются при открытии. Клик по истории / смена даты подгоняет карту под маршрут.
- Экспорт/импорт истории в JSON (при импорте совпадение даты — из файла). localStorage привязан к браузеру и пути файла.

## Страница «Прозрачность воды»
- Курорт задаёт заплыв: `window.SWIM_CLARITY_LOC = {id, name, lat, lng}` (Нячанг — полная настройка прозрачности,
  остальные — одна точка без реки, норма нячангская); смена курорта перезагружает фрейм; значения от «старого» места
  отбрасываются по `locId`. Лог прозрачности у каждого места свой.
- Отдельный проект nhatrang-water (свой README, свой цикл версий). Вставлен в этот файл целиком: `site/index.html` v3.7,
  base64 в `<script type="text/plain" id="clarityB64">`, грузится во фрейм `srcdoc` при открытии (скрыто).
  Причина вставки: сайт на Netlify ещё не опубликован, а файл заплыва скачивается с суффиксами (`swim_tool_3.html`) —
  ссылки между двумя файлами ломались бы. После публикации можно заменить на `iframe src="https://….netlify.app"`.
- Обновить прозрачность: взять новый `index.html` проекта → base64 → заменить содержимое `clarityB64`.
- Прозрачность v3.3 во фрейме присылает `postMessage({type:'clarity', v, verdict, date, today, win, winName, label,
  loc, locId, strategy, norm, src, at, air, sst, uv, tide:{from, to, delta, dir}, wind (км/ч), windDir (откуда), onshore, alts:[{name, v, prim, shadow}]})` — прогноз на ближайшее окно (до 10:00 — сегодня утро, до 18:00 — вечер, позже — завтра утро).
- Группа погоды — отдельная первая строка шапки, над параметрами, слева; элементы той же высоты, что поля;
  клик — страница прозрачности.
  Только иконки и числа, слова — в подсказках:
  👁 `1 м` — прозрачность, цвет по оценке (мутно < 1.5 коричн. / так себе < 3 охра / нормально < 5 серо-бирюз. /
  хорошо < 8 зелён. / отлично — тёмно-бирюз.); 🔆 `6,8` — УФ (макс. за окно), цвет по шкале УФ (< 3 зелён., < 6 жёлт.,
  < 8 оранж., < 11 красн., дальше фиолет.); 🌤 `26°` — воздух; 🌊 `29°` — вода (средние за окно, целые);
  🌙 `↑ +0,1 м` — прилив/отлив: одна цифра — изменение уровня за окно (при отливе отрицательная), стрелка остаётся;
  в подсказке — уровни в начале и конце окна; 💨 `3 м/с ↙` — ветер, средний за окно, стрелка — куда дует;
  в подсказке км/ч, откуда и «с моря / с берега».
  В подсказке 👁 — значения всех стратегий (★ основная, «фон» — фоновые, копят статистику).
- Иконка удаления от берега — своя SVG на прозрачном фоне: две волнистые кривые (сверху берег — коричневая, снизу линия
  заплыва — голубая), между ними вертикальная двусторонняя стрелка. Эмодзи-стрелка заменена.
- Иконка кнопки «линия берега OSM» — SVG-квадратик со скруглёнными углами: суша тёплая светло-бежевая #ECE6DA, море
  насыщенно-голубое #4AA8F0 (оттенки Google Карт, насыщеннее — контраст тёплое/холодное), берег — тёмная линия.
  Выключено — иконка бледная (opacity 0.45), включено — яркая на голубом фоне кнопки.
  Последнее значение хранится (`swim.clarity.v1`), при открытии показывается сразу, свежее приходит из фрейма.
- Клик по 👁 — страница прозрачности поверх всего, сверху «← Заплыв». Открыта ссылка с `#sync=…` — сразу страница
  прозрачности (её синхронизация через Google Таблицу работает и во фрейме).
- Страница прозрачности — шаг истории браузера: открытие = `history.pushState({clarity:1}, '#clarity')`; «Назад»
  (кнопка, жест, кнопка мыши) — к заплыву, «Вперёд» — снова прозрачность (`popstate` по `state.clarity`);
  «← Заплыв» = `history.back()` (шаги не копятся). Открыт файл с `#clarity` или `#sync=…` — шаг заплыва без хэша
  подкладывается снизу, «Назад» ведёт на заплыв.
- Поле 👁 «Видимость по ощущениям» — первая строка, справа от 🗑️: метры (`3`) или поправка к прогнозу (`+1`, `−0,5`),
  пусто — удалить. Пишется замером в журнал прозрачности без перехода: `postMessage` во фрейм
  `{type:'clarity-fact', id, date, win, value, time}`; дата — из 📅, окно — по времени «с» (до 13:00 утро `am`, позже
  вечер `pm`), время замера — время «с»; место — курорт заплыва. Ответ `{type:'clarity-fact-ack', id, ok, actual, error, locId}`.
  До готовности фрейма сообщения в очереди (готовность — первое сообщение `clarity`; смена курорта — снова очередь;
  сообщения для другого места выбрасываются). Источник один — журнал прозрачности: при смене даты и при старте
  запрос `clarity-get-fact`, поле показывает его значение. Поменялось время «с» и окно сменилось — замер переезжает
  (старый удаляется, новый пишется). Без «с» — ⚠️ «укажите время «с»»; план (будущая дата) — поле выключено.
  В записи: `feelVis` (м), `feelAt {date, win, loc}`; колонка 👁 в истории (перед курортом), в подсказке окно.
- localStorage общий (тот же файл/адрес): лог прозрачности `ntClarity.*` и данные заплыва `swim.*` не пересекаются.
